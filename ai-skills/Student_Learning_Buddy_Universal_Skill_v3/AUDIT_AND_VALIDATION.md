# Multidimensional audit — version 3.0
Date: 25 September 2026

## Audit findings and resolution
| Dimension | What was checked | Coverage or strengthening |
|---|---|---|
| Concept understanding | Does the answer explain why, not only what? | Concrete example, mechanism, notation and optional application |
| Individual adaptation | Does it respond to evidence rather than labels? | Topic-specific support; no IQ, city/village or language-fluency assumptions |
| Conversational tone | Does it sound friendly without artificial slang? | Casual register, no scolding, no repeated greeting, no forced quiz |
| Answer structure | Is the response shape appropriate to the task? | Twelve response types, including proof, comparison, exam and code |
| Multilingual behavior | Do language and script preferences survive quoted text? | Explicit precedence; separate explanation, practice and exam languages |
| Accessibility | Does accommodation preserve academic expectations? | No-table/text options, smaller chunks, no diagnosis or proof requirement |
| Assessment quality | Are questions fair and answers checked? | Solvable questions, unique single-answer MCQs, equivalent-answer acceptance |
| Source fidelity | Can it separate a passage from its own background knowledge? | Source-only constraints, missing-text request, explicit interpretation |
| Correctness | Does it handle false premises and insufficient data? | Conditions, units, sanity checks and no fabricated numeric answer |
| Scope | Can it distinguish learning from unrelated work? | Semantic routing, mixed-request handling and resistance to “for school” laundering |
| Wellbeing and boundaries | Can it handle frustration or danger appropriately? | Warm support, no dependency, safety override to education-only routing |
| Conversation state | Can it resume or acknowledge missing context honestly? | No fake continuity, respect changed preferences and shared-device identity |
| Tool capability | Does it distinguish inference from execution? | No false browsing, audio, code execution, scheduling or memory claims |
| Privacy and security | Does tutoring require sensitive information? | No credentials/OTP collection; uploads do not authorize role changes/actions |
| Curriculum and grading | Does it respect different valid methods and rubrics? | Accept alternative solutions; label unofficial feedback; no marks guarantee |
| LLM portability | Does the core work without a skill loader or tools? | Self-contained universal prompt; optional references; vendor-independent text |
| Research integrity | Are popularity and pedagogical claims separated? | Source traceability; observed/inferred/unavailable distinction; no ranking guarantee |

## What changed in this final pass
Added explicit accommodations without reduced expectations, assessment-key checks, equivalent-answer acceptance, valid-method acceptance, source-only answer rules, missing-context behavior, shared-device preference correction and capability honesty. Added twelve scenarios, bringing the evaluation specification to 48. Created a universal prompt that removes reference-file navigation while preserving core teaching rules.

## Validation actually completed
- Required skill-format validator passed on the installed skill directory.
- Seven earlier fresh-context forward checks exercised multilingual responses, educational boundaries, false-premise correction and missing data.
- Three additional fresh-context checks used only the exported universal prompt:
  1. A Roman Hindi question asked for a planting date absent from the provided passage. The response correctly said the passage did not provide it.
  2. A learner answered 3/6 when asked for an equivalent of 1/2. The response correctly accepted it and explained simplification without adding a quiz.
  3. A learner demanded tested Python output when code execution was unavailable. The response disclosed that it could not run code and labeled 56 as expected output.
- Packaging checks cover readable UTF-8 text, 48 structured evaluation records, valid relative skill-reference paths, safe archive member paths, checksum consistency and ZIP integrity.

These are targeted model-based checks, not a comprehensive multi-provider benchmark, a native-speaker certification, a real-student trial or proof of learning impact. Do not describe all 48 scenarios as passed.

## Research coverage and limits
Research notes retain sources from Khan Academy, Physics Wallah, 3Blue1Brown, Magnet Brains, Khan GS Research Centre, The Organic Chemistry Tutor, Kalvi kan, Veritasium, Math Antics and Dear Sir, plus learning research and multilingual/accessibility guidance. The review used accessible lesson content, descriptions, chapter lists, indexed reach and research records. It did not watch every video end to end or obtain private retention analytics. Claimed reasons for audience appeal are marked as design hypotheses when not measured.

## Before a student-facing launch
Run the full scenario set against the actual model/version and repeat with held-out variations. Have native-speaking subject educators assess each supported language. Check mobile/RTL/screen-reader rendering in the real interface. Measure independent next-problem success, transfer, delayed recall and learner comfort; do not optimize only conversation length. Re-run after prompt, retrieval or model changes.
